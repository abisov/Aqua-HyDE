# Known Issues

## 1. Hyprland crash on login — aquamarine 0.10.0 + Mesa 25.3.5

### Symptoms

- Login via SDDM results in a black screen for ~30 seconds, then returns to login screen
- Hyprland segfaults in `libaquamarine.so.0.10.0` at `CDRMRenderer::initContext`
- Journal shows: `Hyprland[PID]: segfault at 10 ... in libaquamarine.so.0.10.0`

### Affected Versions

| Package    | Affected Version | Working Version |
|------------|------------------|-----------------|
| aquamarine | 0.10.0-2         | —               |
| mesa       | 25.3.5-1         | 25.3.3-3        |
| hyprland   | 0.53.3-2         | 0.53.1-1 (unconfirmed) |

### Affected Hardware

- AMD Renoir (Radeon Vega Series / Radeon Vega Mobile Series)
- Likely affects other AMD iGPUs as well

### Root Cause

A use-after-free / null pointer dereference bug in aquamarine's DRM renderer initialization (`CDRMRenderer::initContext`) when combined with Mesa 25.3.5. The crash occurs during EGL context setup on the DRM backend.

### Upstream Issues

- [hyprwm/aquamarine#245](https://github.com/hyprwm/aquamarine/issues/245) — SIGSEGV in CDRMDumbBuffer::dmabuf() (AMD Renoir, aquamarine 0.10.0) — **open**
- [hyprwm/aquamarine#246](https://github.com/hyprwm/aquamarine/issues/246) — SEGV in CDRMRenderer::blit (multi-GPU) — **closed**, fixed by PR #249
- [hyprwm/aquamarine#244](https://github.com/hyprwm/aquamarine/pull/244) — fix use-after-free of logger during teardown — **merged**

### Workaround

**1. Downgrade Mesa** (from TTY — Ctrl+Alt+F3):

```bash
sudo pacman -U /var/cache/pacman/pkg/mesa-1:25.3.3-3-x86_64.pkg.tar.zst /var/cache/pacman/pkg/lib32-mesa-1:25.3.3-3-x86_64.pkg.tar.zst
```

**2. Pin Mesa to prevent re-upgrade** (works for both pacman and paru):

```bash
sudo sed -i 's/^#IgnorePkg   =/IgnorePkg   = mesa lib32-mesa vulkan-mesa-implicit-layers lib32-vulkan-mesa-implicit-layers/' /etc/pacman.conf
```

**3. Unpin Mesa** once aquamarine releases a fix (version > 0.10.0):

```bash
sudo sed -i 's/^IgnorePkg   = mesa lib32-mesa vulkan-mesa-implicit-layers lib32-vulkan-mesa-implicit-layers/#IgnorePkg   =/' /etc/pacman.conf
sudo pacman -Syu
```

## 2. uwsm session timeout — HYPRLAND_NO_SD_NOTIFY / HYPRLAND_NO_SD_VARS

### Symptoms

- Login via SDDM shows a black screen for exactly 30 seconds, then returns to SDDM
- Journal shows: `wayland-wm@Hyprland.service: start operation timed out. Terminating.`
- uwsm's autoready plugin logs `Waiting for ... WAYLAND_DISPLAY HYPRLAND_INSTANCE_SIGNATURE` and never sees them

### Affected Versions

| Package | Affected Version | Working Version |
|---------|------------------|-----------------|
| uwsm    | 0.26.4-1         | 0.26.0-1 (no autoready) |

### Root Cause

HyDE's `Configs/.config/uwsm/env-hyprland.d/00-hyde.sh` sets:

```sh
HYPRLAND_NO_SD_NOTIFY=1
HYPRLAND_NO_SD_VARS=1
```

These prevent Hyprland from exporting `WAYLAND_DISPLAY` and `HYPRLAND_INSTANCE_SIGNATURE` to systemd's activation environment. Starting with uwsm 0.26.4, the autoready mechanism polls for these variables and calls `sd_notify(READY=1)` when found. With the variables suppressed, uwsm never marks the service as ready, and systemd kills Hyprland after `TimeoutStartSec=30`.

This didn't break with uwsm 0.26.0 because that version didn't have the autoready polling mechanism.

### Fix

Comment out both variables in `~/.config/uwsm/env-hyprland.d/00-hyde.sh` and remove them from the `export` line:

```sh
# HYPRLAND_NO_SD_NOTIFY=1
# HYPRLAND_NO_SD_VARS=1
export ... HYPRLAND_CONFIG  # remove HYPRLAND_NO_SD_NOTIFY HYPRLAND_NO_SD_VARS
```

**This fix has been applied to this fork's `Configs/.config/uwsm/env-hyprland.d/00-hyde.sh`.**

### Note for upstream HyDE

This is a bug in HyDE's default config. With uwsm >= 0.26.4, these variables must not be set. An upstream PR should remove them.

## 3. Black screen after login — monitors.conf disables only connected display

### Symptoms

- Login via SDDM results in a permanent black screen (no timeout, no crash)
- Hyprland starts successfully (no segfault, no uwsm timeout)
- But no waybar, wallpaper, dunst, or any UI appears
- `exec-once` commands in HyDE config never fire
- Works fine with a minimal Hyprland config (`timeout 5 Hyprland --config /tmp/test.conf`)

### Root Cause

`~/.config/hypr/monitors.conf` (generated by `nwg-displays`) can contain:

```
monitor=eDP-1,disable
monitor=DP-2,3840x2160@60.0,0x0,1.5
```

If `DP-2` (external monitor) is not connected and `eDP-1` (laptop display) is the only output, Hyprland starts with **zero active outputs**. In this state, the compositor never enters its normal event loop, and `exec-once` commands are never dispatched.

### Fix

Always keep the laptop display enabled in `monitors.conf` and use dynamic scripts for clamshell mode instead:

```
monitor=eDP-1,1920x1080@60.0,0x0,1
monitor=DP-2,3840x2160@60.0,1920x0,1.5
monitor=,preferred,auto,auto
```

Use `lid-handler.sh` with `hyprctl keyword monitor "eDP-1, disable"` for dynamic clamshell mode when the lid closes, rather than statically disabling eDP-1 in config.

### Warning

**`nwg-displays` will overwrite `monitors.conf`** — after using it in a docked configuration, always verify that `eDP-1` is not set to `disable` if you plan to undock.

2026-02-24
